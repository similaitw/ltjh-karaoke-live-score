## 驗證狀態

## 準備（2 分鐘）

1. 部署 HTTPS Vercel；跨裝置需 Supabase。HTTP 區網 IP 無法開相機。
2. `/cards` A4、100%、關閉頁首頁尾列印。保留白邊、不要鏡像或反光護貝。每頁兩張，marker 黑框約 70mm。
3. 控制台對林語晴開票。正式模式在手機填入管理員代碼。

## 驗收（5 分鐘）

1. `/scan` 啟動相機，先拒絕，應顯示權限說明；在網站權限允許後重試，看到後鏡頭影像。選另一鏡頭再啟動，應切換成功。
2. 卡 01 正向保持約一秒，應為 ID 0/A。順時針轉 90/180/270°，應改為 B/C/D，票數仍是 1。
3. 同框 4 張不同卡、不同方向，應讀取正確。再分區掃完 20 張，移出畫面的卡仍保留票數。
4. 重掃不加票，轉向／下拉更正會改答案。約 45° 斜卡、遮框或未登錄 ID 不應加票。
5. 另一裝置 `/display` 應同步。完成並確認鎖票後，手機轉卡／另一掃描裝置再送票均不得更改；重新整理應保留。
6. 切分頁、背景或離開 `/scan`，相機指示燈應關閉；返回需重啟。確認拒絕權限、占用與旋轉手機不會持續背景錄影。
7. 斷網新增票應報錯且不顯示成功，恢復後重啟。完成評審分數後公布。

## 已知限制

- 合成影像清楚，不代表昏暗、反光、移動、大角度透視與遠距小卡均可讀。請保留黑框白邊、分區靠近、握穩約一秒。
- 零 bit error 策略會漏讀模糊／遮擋卡。純 JS 在主執行緒執行，真機 FPS、電量、發熱未量測。
- 方向以鏡頭影像為準，畫面不鏡像。旋轉手機後，用卡 01 的 A 朝畫面上方校準；掃描中避免旋轉。
- 首次授權後才有完整相機清單；多後鏡頭機型需實際選擇清楚鏡頭。
- 複印同 ID 視為同一人，MVP 僅登錄 20 張。
- Demo 不跨裝置。正式模式無離線佇列，斷線恢復後要重掃。
- 如真機出現可重現誤碼、方向錯誤、凍結，不可宣告驗收完成；依 `MARKER_SPIKE.md` 記錄並評估替代 decoder。
