# Specification

建立一個可直接部署到 **GitHub + Vercel** 的 Web App，現場不需本機伺服器、不需安裝 Android App。學生沒有手機或平板，觀眾使用「實體方向圖卡」投票；老師用 Android 手機瀏覽器開相機掃描，全場票數即時進入競賽系統。

產品語言：繁體中文（台灣用語），手機優先、投影大螢幕友善。

### 技術方向
- Next.js + TypeScript。
- Vercel 部署。
- Supabase 作資料庫與即時同步（若第一階段尚未接 Supabase，先建立乾淨 adapter 並提供 local/dev fallback；正式部署前完成 Supabase）。
- 手機相機使用瀏覽器 `getUserMedia()`，不做原生 App。
- 圖卡採可辨識 ID + 旋轉方向的 fiducial marker（AprilTag / ArUco 或同類方案）。請先做技術 spike，選擇真正能在 Android Chrome / Samsung Internet 類現代瀏覽器中工作的方案；允許 WASM，但不得要求本機安裝 OpenCV。
- 相機影像預設只在瀏覽器端處理，不上傳影像到伺服器、不儲存照片。
- 不依賴 Plickers App 或 Plickers API。

## M0/M1 實作契約

- 單場競賽，四位虛構參賽者、三位評審、20 張圖卡。初始化示範資料中後三位已完成，第一位可走完整流程。正式活動請在 seed 前替換名單並清除示範評分。
- 每位評審對每位選手有一筆 0–100 分，重送覆蓋舊分。評審分 = 已送出分數的算術平均；缺任何必要評審時總分維持待完成，不把缺分當零。
- 圖卡 A/B/C/D 對應 100/80/60/40 分；觀眾分 = 已收集唯一 ID 的平均，不以全體 20 人為分母。
- 總分 = 評審分 × w/100 + 觀眾分 × (100-w)/100，w 是 0–100 整數。預設 70/30；presets 100/0、70/30、50/50、0/100。只在顯示時取兩位小數；排名以未四捨五入總分排序，同分並列（1,1,3）。
- 有權重的項目必須完成才能排名：評審須全數送分；觀眾須至少一票且鎖票。權重為零的項目不阻擋完成。空輪次即使鎖票仍無觀眾分。
- 每位參賽者一輪觀眾投票；全場最多一個 open round。切換演出前先鎖目前輪次。鎖票後不可再改該輪票，不提供重開；其他參賽者可開新輪。
- 公布前所有選手的必要項目完成且無 open round。公布後凍結所有寫入；管理員取消公布可繼續編輯分數／權重，但不解除既有鎖票。
- 圖卡 ID 0–19，順時針 0/90/180/270° = A/B/C/D。三次連續相同辨識才入票；同 ID 最新答案覆蓋。偏離直角 >25° 或非零 hamming error 不採計。
- Demo 在同瀏覽器分頁同步；Supabase 用 Postgres Changes 與 5 秒輪詢跨裝置同步。API 使用 token 授權、revision compare-and-swap 防止整份資料互相覆蓋。
- 相機影像只在 browser canvas 處理；無影像上傳、持久保存、原生 App 或 Plickers 依賴。
